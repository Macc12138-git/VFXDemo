# Shader、材质与原生组件的分工

适用于高清创作中需要实时形变/材质设计，以及明确授权后的 Unity 适配。
浏览器 Canvas/WebGL 是作者工具，Unity Shader 必须针对实际版本、管线和图形 API 编译验证。

## 先选表达，后写 Shader

| 层的本质 | 优先表达 | 注意事项 |
| --- | --- | --- |
| 固定手绘图案，主要在移动/缩放/冷却 | 静态 RGBA + 原生粒子模块 | 不为运动另写逐帧脚本 |
| 噪声、火焰、流动能量的内部翻卷 | 静态数据纹理 + UV 流动/扭曲 + 轮廓遮罩/阈值 + 色带 | 核心形状不能只靠无约束噪声；限制采样与覆盖面积 |
| 手绘笔触需随主体弯曲 | 静态笔触 + 解析轮廓变形/顶点形变 | 明确笔触跟随形变与重绘的差异 |
| 地面环、斩击弧、光束、碎片有几何方向 | 原生粒子 Mesh/Trail 或 MeshRenderer + 材质 | 地面不能永远 View Billboard；移动由游戏宿主承担时写清接口 |
| 软烟/雾 | 静态软边纹理 + 粒子尺寸、颜色/透明度和 Noise | 优先少量有效层次，检查透明 overdraw |
| 发光 | 独立低强度 Additive 层 | 不靠真实 Light；不默认修改全局 Bloom |

这里是选择准则，不表示所有分支都已在本项目验证。新表达路径必须进入对应案例测试。
只有用户明确同意时才考虑单粒子序列帧；“静态贴图不足”先尝试轮廓/遮罩/几何方案。

## 面向使用的配色

作者要求颜色尽量可调：优先分离轮廓/明暗/透明度与可替换的色相，可采用中性纹理、
分区遮罩、色带或几何颜色分区；有必要保留的手绘固有色不强制灰度化。
只有整体乘色 Tint 不等于自由换色，尤其不能据此声称已烘焙的黄、白、灰能够独立调整。
按实际语义暴露主体/高光/烟/次级粒子/微光等必要颜色，并让原生 Start Color / Color over
Lifetime 继续承担逐粒子色差与淡出。避免为了每种颜色另建材质或自定义控制器。
为每个调色项写清 Inspector 位置、影响图层、默认值及与原生顶点色/淡出相乘的关系；
共享材质调色影响所有引用实例。确需单实例配色时说明复制并重新赋材质的范围及其成本，
不默认批量生成材质副本，也不增加脚本调参层。

验收用临时克隆材质：先确认默认画面确有目标图层，再逐项验证跨色相换色和局部 Alpha=0/恢复，
检查目标确实变化、其他分区未被误改且高光/明暗仍可读；不能用空截图或参数存在代替生效证据。
默认配色仍与原稿对照，测试后不把临时配色写回交付材质。
BuildFX V2 的线性数据 atlas + 材质颜色分区是已测案例，不要求其他效果照抄其 UV/编码。

## 数据与时间合同

在 manifest 和材质说明中记录：

- 色图/数据图用途、线性或 sRGB、通道打包、Alpha 类型、UV 坐标和上下方向、Wrap/Filter。
  噪声是否无缝要验证；Mirror 是可选策略，不是所有纹理的默认答案。
- 逻辑尺寸、裁切矩形、有效透明范围、根锚点和 PPU；变形后边界仍须有足够 padding。
- 参数的单位、默认值、范围和耦合关系，尤其速度、周期、粒子寿命、UV 重复次数。
- 时钟是全局时间、原生粒子年龄还是归一化年龄；是否允许暂停、重新播放、逐实例相位偏移。
  使用原生 Custom Data 可表达独立生命周期；不要用全局 `_Time` 假装能随单实例暂停。
- Vertex Streams 的通道、顺序、维度与 HLSL 输入须一一对应；Custom1 不能只配 CPU 曲线
  而漏 Renderer 的实际顶点流。记录 UV2 是否为通道对齐所需，别照抄另一版布局。

Brazier 噪声例用 Custom1.x 年龄秒数、`t=age*Flow`，核心 Duration/Lifetime 及曲线乘数为
`8/Flow`；不是适用于所有效果的定律。改 Flow 要一起调整相关时钟，复测循环接缝。

## 渲染合同与画面校准

1. 确认实际渲染管线、颜色空间和目标平台，不把 Built-in 附件直接当 URP/HDRP 成品。
   附件用于理解逻辑，不能自动授权其附带的构建、上传或外部脚本操作。
2. 明确 Straight Alpha / Premultiplied Alpha / Additive 的输出与 Blend 配对、ZWrite、
   ZTest、Cull、Queue、Sorting Layer/Order。粒子排序与材质队列共同决定画面，不靠乱增队列修所有问题。
3. 只在正确阶段进行颜色空间转换。区分色图的硬件解码、Shader 生成的 RGB、原生粒子顶点色
   和材质 Tint；各有来源，不能全部无条件 `.linear`。用已知色块及深浅底色测试重复转换。
4. Canvas 8-bit 加法与 Unity 线性加法不等价；独立调光晕而非破坏主体色阶。Bloom、HDR、
   色调映射、曝光和相机设置写进对照条件。白热区域不能吞掉火舌/笔触的结构。
5. 有实际穿插问题时再选软粒子/深度淡化、深度纹理或额外 Pass；它们有采样/渲染成本，
   不是“高质量特效”必须默认开启的功能。若需项目级设置改变，先说明范围。
6. 裁切透明空白可降低覆盖，但要保持锚点、UV 和形变边界。单粒子尺寸不等于有效图案尺寸，
   Stretched Billboard 的纹理长度轴要在实际平台渲染检查。

## 参数复用与合批意识

优先复用兼容的 sharedMaterial，以顶点色、原生尺寸/旋转、Custom Data 表达实例差异。
不要无意调用 `renderer.material` 复制大量材质；但确实不同的 Blend/Pass/贴图需求也不能
为了数字好看强塞一个材质。先记录差异，再用 [性能流程](performance.md)看实际批次原因。

Shader 尽量少且明确：主形材质可以比通用静态粒子复杂；共享最小必要逻辑，不制造包含
一切功能的巨型分支 Shader。评估重复采样、复杂 `pow/sin`、透明屏幕面积和额外 Pass，
通过对照测量决定简化。CBUFFER/SRP Batcher 兼容性有助 CPU 提交，不等于跨系统合成一次 Draw。

## 验证要求

- 外部编辑 Assets 后刷新并等待实际编译完成；连接恢复后重验目标，不切换到别的 Editor。
- 查看目标 Shader 的编译错误及支持状态；在预期图形 API 上渲染，不只运行 C# 编译检查。
- 用临时克隆材质验证关键参数端点（例如 dissolve=0/1）、图层开关、色阶和时钟；恢复并销毁
  测试克隆，不写坏作者材质。参数影响哪几层需要明确，不要求每个 Shader 都有 Dissolve。
- 对比独立主形、次级层、组合、深浅底色、实际屏幕尺寸与斜视角。Mesh/地面效果检查深度、
  剔除和透视，不用正面截图替代。解析近似与原稿逐像素一致是不同结论。
- 在 Player/目标 API 上核验材质和必要变体，避免仅 Editor 可见而打包丢变体；没有构建条件时
  标注未验证，不能擅自发布。变体剔除和打包设置调整须有明确对象和授权。
